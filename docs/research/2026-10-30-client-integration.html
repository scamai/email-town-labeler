02 / 产品目标

让人每天先看到该处理什么，同时保留积压与未分类邮件。

  1. 需要处理：先提供所有日期的 action needed 入口，再提供“今天收到”的子筛选；不能让昨日积压消失。
  2. 待检查：新发件人、尚未分类及同步异常的邮件要有可见入口，不能把“模型没贴标签”等同于“不重要”。
  3. 稍后批量看：订阅、促销、订单、旅行等分类集中查看，用户仍在熟悉的客户端阅读和回复。

这些是建议入口，尚未创建。Gmail 可用搜索和标签；Outlook for Mac 官方支持保存搜索；Apple Mail 有智能邮箱。具体条件组合、跨账户范围和固定入口的操作成本需要实际试用。Gmail 搜索 · Outlook 保存搜索

“需要处理”是模型判断，不是已验证的未完成任务。当前引擎把分类标签增删当成纠错反馈；读过也不代表做完。第一轮应明确完成规则，再决定采用用户主动归档退出收件箱，或新增独立完成标记。不要用移除分类表示完成，也不要让模型自动归档来制造收件箱清空的效果。capture_feedback 实现

日期筛选按用户时区定义“今天”；Gmail 的 newer_than:1d 是最近一天，不等于自然日。会话视图也可能合并不同日期的邮件。当前数据库记录历史分类决定，不能直接把它的条数当成实时待处理数量。

03 / 方案取舍

先利用已有同步；插件和小软件按具体缺口加入。

手机阅读：左右滑动表格可查看完整内容，包括右侧的限制与待验证项。

方式适用用途建议与边界
原生标签／文件夹＋固定入口最快让现有 Gmail 分类可见、可查，并在原客户端阅读回复。优先；显示与打开已实测。纠错写回、归档语义、跨账户保存视图还需验收。
轻量管理软件多账户登录、模型下载、运行状态、异常修复、引导创建客户端入口。值得作为下一阶段。保留现有引擎；不必先实现撰写、附件和完整收发。尚未实现，也未验证安装打包。
Outlook 插件在支持的账户和客户端内提供纠错／处理面板。按目标环境验证。官方矩阵：Mac 的 IMAP CloudCache 可支持，IMAP Direct 不支持；Windows／Web／移动端不支持非 Microsoft 账户插件。不能承诺 Gmail 在所有 Outlook 上通用。
Apple Mail 扩展利用 MailKit 在接收邮件时执行颜色、旗标等允许的动作。可做技术验证；不是任意添加标签徽章或替换原生分类页的接口。后台稍后贴标签能否触发相应扩展动作，尚未验证。
统一分类工作台原生视图不足时，提供一致的跨账户处理列表与完成状态。保留备选。只有实际试用证明现有客户端仍明显增加操作负担，才投入新的邮件展示与状态同步层。

窄屏可左右滑动。工作量为范围判断，没有工期估算或用户效率测量。

插件依据：Outlook add-ins 支持矩阵 · MailKit 消息动作 · Apple Mail 扩展介绍。这些官方能力不代表本项目已有插件；本机 Outlook 的 CloudCache／Direct 模式也未确认。

04 / 推荐推进顺序

第一项验收是现有客户端中的完整闭环。

  1. P0 · 可控邮件验收：由维护者准备专用测试邮件，覆盖今天、昨天、多标签、已读未处理及离线恢复。在每个目标客户端检查分类出现、打开、纠错、服务器回写、学习反馈及完成后的去向。只读显示已通过；涉及真实邮件变更的步骤未执行。
  2. P0 · 固定每日入口：按验收过的条件配置常用分类、今日子视图、全日期需要处理及待检查入口；记录从打开软件到开始处理所需步骤。完成状态先明确再实施；本次未修改客户端持久设置。
  3. P1 · 多账户与可见状态：修正独立实例的服务管理限制，账户、游标、凭据和消息身份保持隔离，共享模型资源。为普通用户提供登录、同步状态和失败恢复的小窗口。
  4. P1 · 真正的 Microsoft 邮箱：新增 Graph 连接器，写原生 categories，测试新邮件、手工纠错、增量同步、授权过期与各客户端显示。不能把现有 Gmail→Outlook 显示当成这项已完成。
  5. P2 · 效果与发行：用获准的实际样本检查中文与各账户误报漏报；再做免命令行安装、OAuth 审核方案、签名公证与升级。通用 IMAP、插件、统一工作台按试用发现的缺口排序。

建议用同一组代表性任务连续试用一周，对照当前使用方式记录耗时、切换次数和重要邮件遗漏；这只是建议的观察窗口，不是开发工期。当前没有测得节省时间或产品市场需求。

05 / 方法与边界

验证方法与边界：显示路径已通过，完整操作仍待测。

检查本地代码及官方文档；通过客户端界面展开分类并打开列表；执行 Gmail 只读搜索；查看 Apple Mail 智能邮箱条件后取消。未发送、移动、归档或改标签，未保存搜索／智能邮箱，未开发或发布软件。没有主动制造新来信，因此不能给出新邮件分类延迟保证。结论限定于本机版本和此次工作 Gmail 账户，不代表 Windows、手机或所有账户配置。

项目进展沿用前次检查：本地分类、纠错学习、断线恢复和资源优化已有基础；Python 测试 495 通过、7 跳过，详见此前代码盘点。本次只改研究资料，未重跑产品测试，既有测试也不能代替以上客户端写操作验收。仓库未发现独立 TODO／ROADMAP；上述排序是新建议，未查询其他外部任务系统。
